# C4 Model

Adds the **C4** lens to the **Diagram** tab of CALM Hub. Provided by FINOS CALM. See
[Install an extension](install.md).

The lens draws an architecture as a [C4 model](https://c4model.com), by the
[CALM C4 standard](../core-concepts/c4.md). You do not change your architecture to get a C4 view: a
C4 mapping gives the C4 kind of each node type.

![The C4 lens: the context diagram of TraderX, with the C4 notes panel](/img/extensions/c4-context.png)

## The diagrams

Select a level, then the system or container in scope in the list next to it. Click an element to
open the next level down.

| Level | Shows | Comes from |
|:--|:--|:--|
| Context | The system in scope, the people who use it and the systems that it talks to | The top-level C4 elements, with the `connects` and `interacts` relationships of their descendants lifted to them |
| Container | The applications and data stores inside the system | The `composed-of` children of the system, or its detailed architecture |
| Component | The parts of one container | The `composed-of` children of the container, or its detailed architecture |
| Deployment | Where each element runs | The `deployed-in` relationships |

![The container diagram of TraderX](/img/extensions/c4-container.png)

![The deployment diagram of TraderX](/img/extensions/c4-deployment.png)

The lens, the level and the scope are in the URL, for example
`?lens=c4&level=container&scope=trading-system`. Thus you can share a link to one diagram.

## Read the diagram

- **Key:** lists the kinds of element on the diagram. Click a kind to dim it or show it again.
- **C4 notes:** names the C4 mapping in use, lists the conflicts with the standard, and tells why an
  element shows at a different kind than its mapping. **Hide** closes the panel.
- **Guessed:** the mapping does not name the node type of this element, so its kind comes from the
  structure of the architecture. Add the node type to the mapping to fix it.
- **External:** a grey element is outside the enterprise, or another team owns it. Its badge gives the
  reason.
- **Selection:** click an element from the open architecture to select its CALM node. The node stays
  selected when you change the lens. An element from a detailed architecture, or the implicit software
  system, has no node to select.

For all the controls, see [C4 lens](../working-with-calm/calm-hub.md#c4-lens).

## Decorators

The lens shows the [decorator overlays](../working-with-calm/calm-hub.md#overlays-on-an-extension-lens)
of the architecture, such as deployments and control evaluations.

| C4 element | Shows the decorators of |
|:--|:--|
| Person, software system, container, component | Its CALM node, and the `composed-of` and `deployed-in` relationships that it is the container of |
| System, container or enterprise boundary, deployment node | The same, on the boundary |
| Relationship | Each CALM `connects` or `interacts` relationship that it stands for, up to 32, errors and warnings only |
| Implicit software system, element from a detailed architecture | None. It is not a node of the open architecture |

A decorated node that the level does not draw, such as a container at context level, shows no badge
on another element. The lens says on the diagram that it is not shown. A relationship on the diagram
that stands for more than 32 CALM relationships shows the decorators of the first 32. The lens says
that the decorators of the others are not shown.

## Use your own mapping

With no other setting, the lens uses the default mapping of the standard. To map the node types of
your organisation, write a [custom mapping](../core-concepts/c4.md#a-custom-mapping) and push it as
the `c4-mapping` default convention of a namespace. Child namespaces inherit it.

```shell
calm hub push convention c4-mapping acme-c4-mapping.json --namespace org --set-default
```

When the mapping that CALM Hub sends is not valid, or a mapping that it `extends` does not load, the
lens shows the error and no diagram. When CALM Hub cannot read the namespace default, it sends no
mapping, and the lens uses the default mapping of the standard.

The service has the default mapping of the standard, so an `extends` of it needs no fetch. Another
mapping that an `extends` names outside CALM Hub must be on an `https` host in `CALM_C4_MAPPING_HOSTS`.

## Settings

| | |
|:--|:--|
| Port | `8093` |
| Export folder variable | `CALM_C4_EXPORT_DIR` |
| CALM Hub sends | The architecture, its detailed architectures in the same namespace, and the `c4-mapping` default of the namespace (`hubData`) |
| Extra setting | `CALM_C4_MAPPING_HOSTS`: the `https` hosts, outside CALM Hub, that a mapping can `extends`. The service fetches only these |
| Source | [`calm-hub-extensions/c4`](https://github.com/finos/architecture-as-code/tree/main/calm-hub-extensions/c4) |

The [README](https://github.com/finos/architecture-as-code/tree/main/calm-hub-extensions/c4#settings)
lists all the settings of the service.
