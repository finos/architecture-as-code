# C4 Model

CALM tools can show an architecture as a [C4 model](https://c4model.com): system context, container, component and deployment diagrams. The **CALM C4 standard** sets how CALM nodes become C4 elements. You do not change your architecture to get a C4 view.

The standard has two parts:

- A **C4 mapping**: a JSON document that gives the C4 kind of each node type. CALM publishes a [default mapping](https://calm.finos.org/standards/c4/1.0/calm-default.c4-mapping.json). Your organisation can write its own mapping.
- **Rules** for the node types that the mapping does not name, and for external elements.

## The default mapping

| CALM `node-type` | C4 kind |
| --- | --- |
| `actor` | person |
| `system` | software-system |
| `service`, `database`, `webclient`, `data-asset`, `ldap` | container |
| `ecosystem` | enterprise-boundary |
| `network` | deployment-node |

## A custom mapping

A custom mapping gives the C4 kind of your own node types. Use `extends` to start from the default mapping:

```json
{
  "$schema": "https://calm.finos.org/standards/c4/1.0/c4-mapping.json",
  "unique-id": "acme-c4-mapping",
  "extends": "https://calm.finos.org/standards/c4/1.0/calm-default.c4-mapping.json",
  "node-types": {
    "aws:lambda": "container",
    "acme:module": "component",
    "acme:vendor-platform": { "kind": "software-system", "external": true },
    "k8s:cluster": "deployment-node"
  },
  "nesting": "demote"
}
```

- **Kinds:** `person`, `software-system`, `container`, `component`, `deployment-node`, `enterprise-boundary` and `hidden`. Tools do not show a `hidden` node or its relationships. Its children take its place.
- **`extends`:** the entries of the mapping replace the entries of the mapping that it extends, for each node type. A mapping with no `extends` replaces the default mapping.
- **`external`:** every node of the type is outside the enterprise.
- **`nesting`:** what to do with a node at the wrong depth, such as a container inside a container. `demote` (the default) shows it one level below its parent. `strict` keeps the mapped kind and reports a conflict.

## How CALM finds the C4 model

Only `composed-of` sets the C4 hierarchy. When the mapping does not name a node type, the structure sets the kind:

1. A top-level node with `composed-of` children, or a top-level node with no children, is a software system.
2. A child of a software system is a container. A child of a container is a component.
3. `deployed-in` sets the deployment diagram only.
4. `details.detailed-architecture` holds the next level down, in a different document.
5. Containers that no software system holds belong to one implicit software system, named after the architecture.

Tools mark an element whose kind comes from the structure as **guessed**. Add its node type to your mapping to fix the kind.

A node is **external** when one of these rules applies:

| Rule | When |
| --- | --- |
| E1 | It is a software system other than the system in scope |
| E2 | The architecture has an `enterprise-boundary` node, and the node is not inside it |
| E3 | Its detailed architecture is in a CALM Hub namespace that is not the namespace of this architecture, or below it |
| E4 | The mapping marks its node type `external` |

The projection also reports **conflicts**. For example, a person inside a system, or a component with no container above it.

## Which mapping a tool uses

| Tool | Mapping |
| --- | --- |
| [CALM Hub](../working-with-calm/calm-hub.md#c4-view) | The `c4-mapping` default config of the namespace, or of its nearest parent namespace. Else the default mapping |

TypeScript tools can use `projectC4` from `@finos/calm-models/c4`.
